# Lux 对局助手：产品与界面模型

## 产品目标

进入选人或对局后，在几秒内看清双方是谁、最近状态如何、数据来自多少场。需要进一步判断时，在原阵容旁展开玩家或单局资料。已有功能围绕这个流程组织，不增加需要学习的评分和标签。

主流程是 **看阵容 → 比较近期表现 → 核对样本 → 下钻单局**。复盘使用同样的结构，但明确标记为历史复盘。

## 页面职责

| 工作区 | 用户问题 | 主要内容 |
| --- | --- | --- |
| 对战助手 | 这十个人最近表现如何？ | 双方阵容、段位、近期胜负、场均 K/D/A、常用英雄 |
| 选人助手 | 这局可以选什么？ | 公开选择、可选池、模式强度、Buff/Debuff、对位参考 |
| 战绩分析 | 我最近打得如何？ | 自己的比赛与单局详情 |
| 战绩查询 | 这位玩家具体如何？ | 查询、模式筛选、英雄样本和战绩详情 |
| 自动选禁 | 按什么规则执行选择？ | 顺序、保护规则、延迟和总开关 |

## 对局信息结构

双队伍上下排列，每队五列。玩家卡片保持相同的信息位置，避免阅读时不断寻找字段。

1. **身份**：当前英雄头像、玩家名称、段位。Riot ID 编号次级显示，完整名称可悬停读取。
2. **核心表现**：近期胜率和场均击杀 / 死亡 / 助攻。胜率旁直接显示有效场数，三个战斗数字使用等宽数字特性。
3. **分析视角**：默认显示当前英雄在本批样本中的场数和胜率；切换“团队贡献”后显示伤害、承伤和经济的平均队内占比。
4. **近期战绩**：最近十场，按从新到旧纵向排列。每行显示头像、胜负文字、日期、K/D/A；悬停可读取模式和完整时间。窄窗口省略行内日期。
5. **进一步查看**：样本常用英雄与“详情”入口。玩家名称、详情及战绩行均能进入对应侧栏。

队伍标题中的“样本胜率”汇总当前统计范围内所有可读玩家的胜场数 / 场数，同一场比赛在不同玩家中分别计数。它只用于描述这些玩家的历史样本，不是这局的预测胜率；说明放在悬停内容与页脚。

## 阅读与颜色

- 中文使用 Windows 系统字体；核心数字 16–24 px、玩家名称 14 px、段位 12 px，辅助信息 10–12 px。
- 中文名称使用中等字重，标题和重要数字适度加重；不再使用 7–8 px 的战绩数字。
- 蓝色与粉色细线区分己方和敌方；浅绿、浅红表示胜负，并同时保留胜负文字。
- 深浅主题使用独立的语义色和文本对比，避免所有统计字段都采用高饱和彩色标签。
- 相同位置表达相同含义，未知值显示“—”，未公开身份、加载中和读取失败有各自说明。

## 交互模型

玩家侧栏显示当前范围的贡献、英雄样本与已读取比赛。长列表复用虚拟化组件，选中英雄只筛选列表，不悄悄改变整批统计的范围。比赛侧栏复用现有单局概览、十人数据及贡献雷达。

侧栏支持 Escape、关闭按钮、点击遮罩和焦点约束；关闭后恢复入口焦点，保留各卡片滚动位置。切换对局、账号或统计模式时关闭旧侧栏。打开完整战绩页仍使用已有查询流程。

1280 × 860 及以上优先让十人的身份和核心指标同时可见，战绩列表在卡片内部滚动；大窗口自动获得更多可见战绩行。1060 × 700 的最小窗口保持字号和五列结构，允许工作区纵向滚动，不通过持续缩小数字来塞入全部内容。

## 数据口径与实现边界

- 样本深度沿用 20 / 50 / 100 / 200 场配置。胜率、K/D/A、英雄样本、贡献与最近十场共享同一统计范围。
- 当前英雄的样本表现不代表终身熟练度；贡献占比保留各自有有效分母的场数。
- 实时阵容只显示客户端已公开信息，身份未公开时不制造玩家资料。
- 雷达继续使用“本场最高值为外圈”，队内占比与全场排名分别显示。
- 悬停、视角切换和滚动在 Vue 本地完成。Go 状态保留版本检查与独立玩家引用，不增加鼠标事件到后端的通信。

布局参考用户提供的 LeagueAkari 截图，并阅读其队伍分组、玩家头部与近期战绩列表源码。WeGame 作为用户提出的体验方向；本轮没有核验其当前版本界面，不声称逐项复刻。

## 战绩分析工作区（0.2.2）

页面默认聚焦 **选比赛 → 看核心表现 → 比较十人 → 查看贡献**。顶部保留玩家、段位、近期胜负和场均 K/D/A；移除重复的“我的近期表现”、更新时间和大型 KDA 比值。模式控制统筹本批统计，英雄与胜负筛选仅作用于列表，避免把筛选后的几场悄悄解释成整个样本。

左侧战绩由每行 100 px 收紧至 78 px，保留胜负文字、英雄、K/D/A、模式、日期和时长。支持方向键、Home、End；虚拟列表通过比赛 ID 保持选择与焦点。默认窗口能看到更多比赛，长列表仍只创建可见与预加载记录。

右侧依次显示本场英雄与结果、K/D/A、四项核心数据、双方五人表格。伤害占比取本场己方分母；补刀及每分钟补刀合并显示。双方表格有明确的列标题，可在伤害和经济间切换，细条以本场同项最高值作比较；当前查看玩家使用淡色背景与标记。

贡献页在有足够宽度时将雷达、队内占比放左侧，全场十人排名放右侧，使默认窗口能完整比较。窄窗口优先保持文字可读并允许内容区滚动。

解释信息使用统一的信息提示按钮，支持悬停、键盘焦点和 Escape。提示进入当前侧栏的原生对话框图层，避免被裁切；滚动或改变窗口时收起，不监听鼠标移动。来源、统计公式、有效样本条件和更新时间只在需要时出现。查询失败保留明确错误，部分读取仍显示“部分数据”状态。

近期队内贡献与常用英雄归入默认收起的“近期概况”；点击展开后仍可按英雄筛选。全局标题下的描述、页脚重复连接文字以及对战页常驻统计说明也改为按需查看。


## 大乱斗快捷侧栏

选人助手新增独立侧挂窗口。当前英雄和模式 Buff / Debuff 在上方，个人预选以独立一行显示客户端分配的 2–3 个英雄，保持客户端顺序，点击即可选用。公共替补池按当前模式胜率排列，个人预选阶段保留可见但不可交换，结束后开放交换；下方仅显示客户端当前可用皮肤，支持缩略图和当前皮肤标记。长替补池与皮肤列表各自滚动，说明进入悬停提示。

侧栏使用客户端原生拥有窗口关系，与客户端右侧贴齐、顶部与高度对齐，不设置全局置顶，也不因焦点离开而反复隐藏。可以折叠为窄标签、展开、取消贴边或关闭。关闭后本次运行停止自动打开，可从选人助手恢复。客户端最小化、关闭或进入游戏时收起；右侧放不下时优先左侧，再限制在当前显示器工作区。

手动换英雄和皮肤不改变自动选禁开关。每次提交前重新确认账号、阶段、会话与实际当前英雄；个人卡片必须仍在个人预选列表且可选，公共池交换必须仍在替补池，皮肤必须可用。首次未分配英雄时完成本人的 pick action，已有英雄时交换。重叠点击会被拒绝，写入失败不自动重试。客户端原始皮肤可能不在 pickable-skin-ids 中，以 carousel 明确的 unlocked / disabled 状态补足这一例外。

## 对局回放

查询战绩后选择一局，在“对局概览 / 贡献分析”同一行右侧显示回放入口。按客户端状态显示检查、下载、进度、观看、版本不兼容或已失效；原因放在悬浮 / 焦点提示。下载完成后需要用户点击观看，不自动启动游戏窗口。读取失败和终态可显式刷新。

回放文件和播放由客户端管理。服务端使用已查询记录中的原始版本、区服、类型、队列和结束时间，不能用当前版本覆盖未知的历史版本。每次命令重新检查账号和当前可用状态；正在游戏、回放、匹配或选人时不启动另一场回放。仅详情可见时轮询轻量状态，关闭详情停止轮询，鼠标移动不发起读取。

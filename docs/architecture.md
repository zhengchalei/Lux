# Lux 0.2.0 数据与运行时设计

Lux 使用 MyGo 0.8.3 连接 Go 服务与 Vue 3 界面。Windows WebView2 负责布局、绘制和滚动；Go 负责客户端会话、战绩、公共数据与显式开启的自动选禁。前端静态文件和英雄头像嵌入可执行文件，旧 Rust 实现不参与新版运行。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `main.go`、`assets/embed.go` | 桌面生命周期、嵌入资源、窗口与变更事件 |
| `app.go` | 绑定给 Vue 的业务 API，隔离认证与底层传输 |
| `browser.go` | 显式启用的 loopback 浏览器联调服务 |
| `internal/client/runtime.go` | 会话、状态快照、查询调度、取消与结果归属 |
| `internal/client/transport.go`、`discover_windows.go` | 进程/lockfile 发现、LCU HTTP、WebSocket 事件与恢复 |
| `internal/client/scouting.go` | 当前公开阵容的分批玩家查询、逐人重试与发布 |
| `internal/client/automation.go`、`settings.go` | 本人选禁执行与本地设置 |
| `internal/history/` | SGP/LCU 路由、分页、准确队列筛选、比赛补全与共享缓存 |
| `internal/domain/` | camelCase DTO、来源适配、有效样本和准备后的汇总 |
| `internal/publicdata/` | RESG/OP.GG 校验、版本、公共缓存与自动更新 |
| `frontend/src/api.ts`、`store.ts` | IPC、变更订阅、串行快照读取与增量状态合并 |
| `frontend/src/views/`、`components/` | 战绩、选人、对战助手、选禁设置与虚拟列表 |

## IPC 与页面更新

桌面模式通过 `mygo.Bind(app)` 暴露 `App`。客户端认证和传输对象不进入 DTO；Vue 只接收归一化数据，或发起明确的查询和设置操作。正常启动不开放应用 HTTP 端口，只有显式 `--serve 127.0.0.1:PORT` 才启用浏览器联调服务。

主要 API 为 `GetRevision`、`GetSnapshot`、`Lookup`、`QuerySelf`、`ReviewLastGame`、`RefreshBattle`、`RetryScout`、`SetAnalysis`、`GetMatchDetail`、`GetMatchups`、`InspectChampion`、`SaveAutomation` 和 `StopAutomation`。业务异步任务在 Go 中运行，界面读取状态及进度。

Go 将短时间内的更新合并为 `lux:changed` 版本信号，事件不携带整份玩家记录。Vue 在动画帧中合并通知，再串行调用 `GetSnapshot`，避免多个通知造成重叠读取。事件订阅之外保留 3 秒版本恢复校准；无事件通道的开发模式为 800 毫秒。恢复先读取 `GetRevision`，版本未变时不复制和传输整份战绩，避免十人各 200 场时反复处理约 5 MB 的相同快照。

前端按快照版本跳过重复应用，对未变化的玩家、阵容和公共数据保留对象引用。汇总在 Go 中准备，悬停使用 CSS，鼠标移动和滚动不调用业务桥接。长战绩列表和英雄选择网格只构建可见范围；页面仍有数据校准计时器，不是完全无轮询设计。

## 客户端会话与查询

客户端发现读取当前进程或 lockfile。初始 HTTP 快照提供账号、大区、阶段与公开阵容，WebSocket 事件唤醒新快照；连续事件合并，周期校准和 HTTP 恢复用于补偿订阅失效。

账号、大区或平台变化会取消旧会话工作、清除有身份归属的数据并关闭自动选禁。房间读取前后核对账号，查询和阵容另有代次。异步结果发布前再次核对会话和任务归属，按 PUUID 关联玩家，不按界面槽位回填。

玩家资料和战绩不占用状态同步通道。最多运行四条玩家查询流水线，后台最多占三条，为主动查询留出位置；战绩仓库另限制四个同时进行的 HTTP 请求。先加载最多 20 场首批数据，再扩展到配置的 20/50/100/200 场。扩量未结束时保持加载状态，继续加载失败保留已有结果并发布原因。元数据和段位读取失败不伪造资料。

原生界面退出时取消上下文并关闭运行时。公共统计独立运行，自动选禁也有独立执行协程，不等待战绩查询完成。

## 战绩来源与覆盖

SGP 使用经过校验的内置公开服务器目录，并间隔尝试刷新。当前区域与平台只匹配已配置后端，不构造任意跨区地址。entitlements 与 league-session token 从当前客户端获取，仅在内存短暂复用并绑定连接和账号。

自签证书例外只用于固定 loopback LCU 地址。SGP 与公共 HTTPS 验证远端证书；战绩传输禁止重定向，避免认证被转发。对外错误保留必要阶段和 HTTP 状态分类，不展示认证或请求地址。

SGP 可用时按准确队列分页；失败回退当前客户端 LCU，LCU 通过分页扫描后筛选队列。成功空响应与失败区分，分页去重并识别重复页面，限制扫描范围。后续页面失败保留已读取记录。玩家级 403/404 不使其他玩家进入全局冷却；认证、网络及服务级失败短暂冷却 SGP。

历史覆盖字段使用统一的 camelCase 合约：

| 字段 | 含义 |
| --- | --- |
| `requested` | 请求目标场数 |
| `scanned` | 扫描到的唯一记录数 |
| `fetched` | 队列筛选后保留的唯一记录数 |
| `valid` | 满足竞技统计条件的记录数 |
| `complete` | 有效记录中具备本人视角及双方各五人的数量 |
| `source`、`queueId`、`note` | 实际来源、准确队列和降级/边界说明 |

LCU 自动补全限于最新五场符合条件但缺少双方完整数据的比赛，其余按详情请求补全。完整比赛以大区、平台和比赛 ID 为键共享，缓存紧凑序列化字节，上限同时受 256 场和 16 MiB 载荷约束，并使用 LRU 淘汰。同场进行中的补全共享读取，获得执行权后再检查缓存。命中时按当前 PUUID 生成视角，个人战绩与认证不写磁盘。

“复盘最近一局”从 LCU 比赛详情读取明确公开的历史身份并标注历史来源。未提供身份的信息保持未知，历史阵容不作为当前房间展示。

## 统计与详情

胜率为有效胜场除以有效场数。KDA 为总击杀加总助攻除以至少一次总死亡，场均 K/D/A 分别除以有效场数。最近十场、常用英雄和汇总使用同一筛选条件。已知自定义、明确 PVE/非匹配、重开与不足 3 分钟的记录排除，原始记录仍可查看。

完整贡献要求本人视角与双方各五人。贡献先逐局计算相对己方份额，再对该指标的可用样本平均；伤害、承伤和经济独立计数。字段缺失、完整阵容不足或分母为零保持未知，个人摘要不能替代队伍总量。

单局详情分别展示己方份额、全场排名和雷达。雷达每轴以本场该项原始最大值为外圈、全场人均为灰线，排名允许并列。队内占比为 32% 的全场最高伤害仍位于外圈；缺失字段不作为零值参与完整比较。这些数据不表示跨位置能力百分位或对局胜率预测。

## 公共强度与缓存

RESG、普通大乱斗强度和普通平衡调整分别验证并替换，分别记录成功时间；单源失败保留旧数据和旧时间。RESG 模块按 `export default JSON` 解析，不执行下载的 JavaScript。海克斯发布版本变化会清除旧版英雄调整详情。

公共服务启动时刷新，完整成功后 6 小时再检查，失败或部分成功后 5 分钟重试。缓存为 `%LOCALAPPDATA%\Lux\public-statistics-go.json`，旧 `public-statistics.json` 只作为读取后备。公共请求不携带 LCU/SGP 认证。

普通大乱斗强度保留韩服/全段位上下文；排位对位保留韩服/铂金以上、分路、补丁和样本。对位胜率是最终对局胜率，不是对线期胜率；未携带补丁的普通平衡调整独立标注。推荐只使用已读可选池与公开英雄，排位过滤禁用和已占用英雄，大乱斗限定本人当前英雄和替补池。

## 自动选禁与设置

规则保存到 `%LOCALAPPDATA%\Lux\automation.json`，分析偏好保存到 `analysis.json`。支持读取既有 snake_case 与 camelCase 设置，写入兼容旧版的 snake_case。设置缺失或损坏分别回退默认值；每次应用启动总开关均为关闭。

自动选禁仅在用户开启后执行有序候选。选用、禁用分别检查对应可用池，保留队友预选、手动选择、分路与延迟规则；随机大乱斗不执行。提交前重新获取状态并核对会话、阶段、本人未完成动作、候选与规则代次。关闭或切换账号使后续提交失效，不能撤回已发出的请求；结果不明确时不重复发送同一动作。

## 构建与验证边界

`scripts/build-mygo.ps1` 安装锁定前端依赖，执行 Vue 类型检查及构建、Go 测试与 vet，再生成嵌入前端的 Windows 可执行文件和 ZIP。Go 模块要求 1.27.3，Vite 要求 Node.js 20.19+ 或 22.12+。用户运行时只需 Windows x64 与 WebView2，不依赖 Rust 或 Node。

Go 常规测试与 `go vet ./...` 已通过，覆盖来源适配、分页、去重、回退、贡献缺失、缓存、会话归属、设置与选禁计划等逻辑。`TestLiveClientReadonly` 需显式设置 `LUX_LIVE_RUNTIME=1`，使用真实客户端发现和本人查询，不创建房间或开启选禁。

新版原生布局、鼠标/滚动流畅度、进程总内存、200 场真实读取和完整选禁流程需单独实机验证。浏览器开发服务不能替代 MyGo/WebView2 窗口验证，旧 GPUI 的测量和历史联调结论不作为新版验收结果。

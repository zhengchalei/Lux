# Lux 功能补齐分析

调研日期：2026-11-12。目标是 Windows 轻量英雄联盟助手，沿用 MyGo + Go + Vue，优先保持滚动、鼠标响应与低后台开销。

## 结论与本轮落地

Lux 已有自动连接、战绩查询、十人分析、选人侧栏、英雄强度、Buff/Debuff、自动选禁、回放、AI 时间线和更新机制。当前更需要把“看到信息 → 判断 → 查看依据 → 返回原处”连起来，而非继续增加入口。

本轮实现三个明确需求：

1. 单局与战绩记录的主文字使用召唤师名字，英雄保留头像；英雄选择器、常用英雄统计仍显示英雄名，便于选择。
2. 对局与十人面板显示“遇到过”徽标；悬浮或键盘聚焦查看之前的队友/对手记录，点击打开该场详情，保留原页面。
3. 展示“疑似预组队”及证据对局。只统计近 30 天、本局之前、已读取的有效匹配，至少 3 场真实同队；相同对局跨玩家来源去重，重开与自定义不计入。

交手记录本轮基于当前账号已读取的战绩，默认 50 场，可在分析设置提高到 200 场。它不是跨设备或无限期的社交档案。完整长期记录及手工标签作为下一批独立模块，不把已读样本之外的情况显示成“从未遇到”。

### OP.GG：已核对官方桌面产品页

来源：[OP.GG Desktop](https://op.gg/desktop/sc)，官方页面“英雄联盟”详情中明确展示：

- 最新版本增强、削弱、调整信息及分路英雄梯队。
- 单双排、灵活组排、海克斯大乱斗等分模式战绩、常用英雄和近期 KDA。
- 按服务器、段位、版本比较胜率、选取率、禁用率和克制关系。
- 英雄技能加点、推荐符文和出装。

Lux 已覆盖其中的近期战绩和部分强度/对位数据，但目前没有完整的分路版本榜、符文、技能加点及出装方案。现有 `internal/publicdata/sources.go` 的英雄对位接口是可复用入口；还需要新增明确的数据模型、响应解析和版本缓存，不能把对位胜率当作对线期胜率。

### WeGame：已核对官网与官方更新日志

来源：[WeGame 官网](https://www.wegame.com.cn/home/)、[更新日志](https://www.wegame.com.cn/client/changelog/)，结合用户提供的战绩筛选参考。

可借鉴的产品层面是紧凑筛选、阶段明确的助手、战报/个人教练、符文装备推荐和按需解释。官网“助手”宣传中部分示例属于其他游戏，因此不将这些宣传直接列为“当前英雄联盟全部可用功能”。官方更新日志确认其持续优化字体、DPI、鼠标卡顿、窗口响应和游戏模式后台行为，但不足以证明每个 LOL 私有能力均能通过 LCU 取得。

Lux 应借鉴交互与信息层级，不依赖 WeGame 私有服务，也不把宣传截图里的评分复制成无来源的本地评分。

## 产品模型与模块划分

### 1. 玩家档案，而非散落的小开关

统一模型建议包含 `AccountScope { selfPUUID, region, platform }`、`PlayerIdentity { puuid, riotId, icon, level }`、`PlayerNote`、`EncounterRecord`、`PinnedPlayer`。展示页继续使用现有 `Profile`，本地备注与交手资料通过小型独立接口补充，不把长期档案不断塞进周期快照。

交手记录至少保留比赛 ID、服务器、时间、当时双方队伍关系、来源、当时 Riot ID 和可查看状态。历史改名不能让记录断开；切账号不会把上一人的主观备注套给新账号。只有在记录范围超出当前历史窗口时，才需要明确的保留天数与容量上限。

### 2. 选人决策卡，而非多个互不关联的榜单

选人后以当前英雄为中心显示四块：本人可用皮肤、当前模式调整、个人近期样本、符文出装。峡谷另提供分路和对位；大乱斗显示个人 2–3 选项及替补池，推荐只在合法可选范围内。

任何方案至少关联模式、位置、版本、服务器、分段、样本数、来源时间。应用符文或技能前，后端重新核对当前英雄、选人会话和可写状态；用户改变选择后，过期请求不能写入新的英雄配置。

### 3. 复盘页由证据组织

每条结论可以展开“发生了什么、与谁比较、从哪条数据得出”，并跳转时间线对应分钟。没有位置、视野或技能使用数据时，不推断“应该看到”或“技能空了”。先把已有金钱、补刀、经验、击杀事件和目标争夺讲清楚，再接入更细指标。

## 性能与验证约束

- 账号或比赛变化触发分析，鼠标移动、悬浮和滚动不触发历史抓取；徽标读取缓存计算结果。
- 交手索引只针对当前本人已读历史建立；预组队共享去重比赛集合。五人队伍最多 31 个成员子集，规模由当前阵容限制。
- 浮层默认展示最近 8 条证据并独立滚动，长战绩列表继续虚拟化；说明不常驻挤占十人表格。
- 不把组合统计当成本局胜率；不把有共同队友的间接链条当成全员共同组队。
- 关键验证包括改名/同名、双来源重复比赛、同队/对手、历史回看不能读取未来证据、账号隔离、空样本、失败重试、浮层键盘操作与返回原处。
- 符文、录屏、实时面板及自动化新增动作分别设置独立生命周期和测试；不因增加展示功能引入高频全量快照。

## 推荐推进顺序

第一批完成本轮名称、交手证据和预组队，并替换桌面程序、发布单 EXE。第二批优先做玩家档案（备注、收藏、长期交手）与单局装备/符文详情，形成个人长期价值。第三批接入版本化符文出装和按需应用，再深化 AI 证据定位。实时悬浮窗与录屏在前述功能稳定、后台开销有实测预算后独立推进。
